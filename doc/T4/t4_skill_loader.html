01本课目标

亲手写一个 Skill 和一个最小加载器。理解元数据、正文与附属文件分别何时进入上下文；给现有 Agent 增加 load_skill / read_skill_reference 这两个受控工具；观察选择失败与加载失败的区别。

练习方式本课代码是供你亲手输入的教学内容。Agent 维护 doc/ 课件；app/、scripts/ 和配置由你自己创建或修改。先运行独立实验，再按接入说明修改主项目。代码中的演示工具与目录均会明确标注，不把实验结果当作模型端到端验收。

02背景回顾：你的 Agent 还缺什么

当前 get_all_tool_schemas() 聚合内置/MCP 工具,每轮交给模型；build_llm_messages() 只把历史存储记录还原成消息。项目没有 Skill 扫描器或按需读取入口。仅在硬盘新建 SKILL.md,你自己的 FastAPI Agent 不会自动发现它。

应用启动 → 扫描受信任的 Skill 根目录 → 元数据索引
每轮任务 → 索引进入上下文 → 模型选择 load_skill(name)
工具结果返回正文 → 模型按步骤选择现有工具
需要细节 → read_skill_reference(name, relative) → 返回参考文档

Skill 会教 agent 怎样调用 T2 的 CLI 或 T3 的 MCP 工具,但不能凭空提供它们。先明确工具是否真的注册、可调用,再写手册。手册指令也不应覆盖项目“用户亲手改源码”的学习约定。

03原理：格式合同与加载策略

层次存放内容host 的职责
元数据name、description 等 YAML frontmatter发现文件、验证名称与目录对应、建立可用清单。
正文Markdown 步骤显式调用或模型选择后才放入消息。
references详细文档解析允许范围、限制大小、按需读文件。
scripts确定性可执行步骤由执行器按权限调用；不是扫描到文件就自动运行。
assets模板与素材按需要用作输入或产物,不要求全文进入上下文。

“渐进披露”指进入模型上下文的时机,不等于宿主绝不能在发现阶段读取整个小文件。下面扫描器读取 SKILL.md 来验证完整格式,但只把 name/description 放入索引,正文只在 load_skill 时返回。每个 Skill 的元数据仍有成本。

description 是选择线索,不是确定性的函数路由。模型可能漏选或误选;先验证文件是否发现、索引是否注入,再评价提示词。按任务测试比反复换几句漂亮描述更有用。

04动手一：写一份可复用的操作手册

先创建一个 Skill 目录,放入下面两份文件。若在 Claude Code 使用,个人目录可选 ~/.claude/skills/py-hand-check；若给本项目加载器使用,建议你创建仓库根目录 tutorial_skills/py-hand-check。后者是本课自己约定的目录,不会因为目录名而被其他产品自动加载。两处任选相应用途,不要把两个副本长期各自维护。

由你创建：tutorial_skills/py-hand-check/SKILL.md

---
name: py-hand-check
description: Python 代码自查清单。写完或改完任何 Python 代码后、或被要求检查/审查代码时使用。检查项:变量拼写手滑(如 contet/emial/DATATBASE_URL)、函数参数类型标注、泛型参数化(dict/list 不裸写)、改动后是否跑了 ruff 与 mypy 验证。
---

# py-hand-check:Python 代码自查清单

## 第一步:拼写扫描(确定性的事,交给脚本)

对目标文件运行扫描脚本:

    bash ~/.claude/skills/py-hand-check/scripts/check_typos.sh <文件...>

脚本只找已知手滑词。退出 1 表示发现候选问题,报告位置和建议;不要自动改源码。
退出 2 表示扫描失败,先解决文件或命令问题。退出 0 仅表示本词表未命中。
本项目由用户亲手改源码,本 Skill 只检查、讲解并给修改片段。

## 第二步:人工检查(需要判断的事,模型来)

按顺序核对:

1. **拼写与命名**:变量名是否手滑(重点:contet → content、emial → email、
   DATATBASE → DATABASE)。命名风格与所在文件既有风格一致。
2. **参数类型标注**:所有函数参数必须标注类型;`dict` / `list` 裸写不行,要参数化
   (如 `dict[str, object]`);返回类型不写。
3. **Any 边界**:json.loads / 外部响应的 Any 结果必须就近收窄
   (isinstance + cast,或 pydantic 建形状),禁止链式裸取。

## 第三步:验证(不可跳过)

    uv run python -m ruff check <改过的文件>
    uv run python -m mypy <改过的文件>

两条都绿了才算完。跳过验证 = 本次检查不合格。

## 输出格式

按「✅/❌ 检查项 → 位置 → 建议」列表汇报,最后一行给结论。

由你创建：tutorial_skills/py-hand-check/scripts/check_typos.sh

#!/usr/bin/env bash
# 已知手滑词扫描:命中则打印行号并退出 1,通过则退出 0
TYPOS="contet|emial|DATATBASE|retrun|lenght|publich"

if [ $# -eq 0 ]; then
    echo "用法: check_typos.sh <文件...>"
    exit 2
fi

for path in "$@"; do
    if [ ! -f "$path" ] || [ ! -r "$path" ]; then
        echo "无法读取文件: $path" >&2
        exit 2
    fi
done

matches=$(grep -nE "$TYPOS" "$@")
status=$?
if [ "$status" -eq 2 ]; then
    echo "扫描失败" >&2
    exit 2
elif [ "$status" -eq 0 ]; then
    echo "$matches"
    echo "发现手滑词 ↑"
    exit 1
else
    echo "拼写扫描通过"
fi

这份正文里的脚本路径原先指向 ~/.claude/skills。若你选 tutorial_skills 目录,将该命令改为从项目根目录执行 bash tutorial_skills/py-hand-check/scripts/check_typos.sh。这是部署位置适配,不改变 Skill 格式。检查脚本只做关键词匹配,注释、字符串中也可能命中,需要人工判断。

注意现有 Agent 没有通用 Bash 工具,所以只加加载器还不能执行这个 shell 脚本。可先学习正文与引用加载,再用 T2 的 run_cli 为这个固定脚本写受控适配器,不要为方便开放任意命令。

05动手二：最小 Skill 加载器

创建 scripts/t4_skill_lab.py。YAML 使用 PyYAML 的 safe_load；本项目 pyproject.toml 还没有声明 PyYAML 为直接依赖,即使某个环境恰好能 import 也不应依赖偶然安装。独立实验可用 uv run --with pyyaml python 临时补依赖；正式接入由你执行 uv add pyyaml,类型存根可加到 dev 依赖。

由你创建：scripts/t4_skill_lab.py

"""T4:用户抄入 scripts/t4_skill_lab.py;独立的最小 Skill 加载器。"""

import json
import re
from dataclasses import dataclass
from pathlib import Path
from tempfile import TemporaryDirectory
from typing import cast

import yaml


@dataclass(frozen=True)
class SkillCard:
    name: str
    description: str
    directory: Path


def read_limited(path: Path, limit: int = 32_768):
    with path.open("rb") as stream:
        raw = stream.read(limit + 1)
    if len(raw) > limit:
        raise ValueError(f"文件超过 {limit} 字节:{path.name}")
    return raw.decode("utf-8")


def split_skill(text: str):
    lines = text.splitlines()
    if not lines or lines[0] != "---":
        raise ValueError("SKILL.md 必须以 --- 开头")
    try:
        end = lines.index("---", 1)
    except ValueError as exc:
        raise ValueError("缺少 frontmatter 结束符") from exc
    # safe_load 不构造任意 Python 对象;返回值依然是 Any,立即转为 object 再检查。
    try:
        loaded: object = yaml.safe_load("\n".join(lines[1:end]))
    except yaml.YAMLError as exc:
        raise ValueError("frontmatter 不是合法 YAML") from exc
    if not isinstance(loaded, dict) or not all(isinstance(k, str) for k in loaded):
        raise ValueError("frontmatter 必须是字符串键的映射")
    metadata = cast(dict[str, object], loaded)
    name, description = metadata.get("name"), metadata.get("description")
    if not isinstance(name, str) or not re.fullmatch(r"[a-z0-9]+(?:-[a-z0-9]+)*", name):
        raise ValueError("name 仅允许小写字母、数字、单个连字符")
    if len(name) > 64 or not isinstance(description, str) or not description.strip() or len(description) > 1024:
        raise ValueError("name/description 长度或类型不合法")
    body = "\n".join(lines[end + 1 :]).strip()
    if not body:
        raise ValueError("本练习要求正文非空")
    return name, description.strip(), body


def scan_skills(root: Path):
    root = root.resolve(strict=True)
    cards: dict[str, SkillCard] = {}
    for path in sorted(root.glob("*/SKILL.md")):
        resolved = path.resolve(strict=True)
        if not resolved.is_relative_to(root):
            raise ValueError("Skill 符号链接越出目录")
        name, description, _ = split_skill(read_limited(resolved))
        if name != path.parent.name or name in cards:
            raise ValueError("Skill 名称必须与目录一致且不能重复")
        cards[name] = SkillCard(name, description, resolved.parent)
    return cards


def build_index(cards: dict[str, SkillCard]):
    # 索引只包含元数据;正文没有被送进模型上下文。
    return json.dumps([{"name": c.name, "description": c.description} for c in cards.values()], ensure_ascii=False)


def load_skill(cards: dict[str, SkillCard], name: str):
    card = cards.get(name)
    if card is None:
        raise ValueError(f"未知 Skill:{name}")
    path = (card.directory / "SKILL.md").resolve(strict=True)
    if not path.is_relative_to(card.directory):
        raise ValueError("Skill 正文越出已发现目录")
    found_name, _, body = split_skill(read_limited(path))
    if found_name != name:
        raise ValueError("文件已改变,请重新扫描")
    return body


def read_reference(cards: dict[str, SkillCard], name: str, relative: str):
    card = cards.get(name)
    if card is None:
        raise ValueError("未知 Skill")
    base = (card.directory / "references").resolve(strict=True)
    # 先检查 references 本身,防止它是一个越出 skill 的符号链接。
    if not base.is_relative_to(card.directory):
        raise ValueError("references 越出 Skill 目录")
    target = (card.directory / relative).resolve(strict=True)
    if not target.is_relative_to(base) or not target.is_file():
        raise ValueError("只允许读取该 Skill 的 references 文件")
    return read_limited(target)


def main():
    # 可运行自测不安装全局 Skill,也不连接模型。
    with TemporaryDirectory() as tmp:
        root = Path(tmp)
        folder = root / "py-hand-check"
        (folder / "references").mkdir(parents=True)
        (folder / "SKILL.md").write_text(
            "---\nname: py-hand-check\ndescription: 检查 Python 参数类型和拼写。\n---\n"
            "先运行检查,再阅读 references/types.md。正文标记 ONLY_BODY。",
            encoding="utf-8",
        )
        (folder / "references/types.md").write_text("参数必须标注,返回类型可省略。", encoding="utf-8")
        (root / "outside.txt").write_text("不允许读", encoding="utf-8")
        cards = scan_skills(root)
        assert "ONLY_BODY" not in build_index(cards)
        assert "ONLY_BODY" in load_skill(cards, "py-hand-check")
        assert "参数" in read_reference(cards, "py-hand-check", "references/types.md")
        for operation in (
            lambda: load_skill(cards, "missing"),
            lambda: read_reference(cards, "py-hand-check", "../outside.txt"),
            lambda: split_skill("---\nname: bad\ndescription: [不是字符串]\n---\nx"),
        ):
            try:
                operation()
            except ValueError:
                pass
            else:
                raise AssertionError("应拒绝非法输入")
        print("T4:元数据/正文隔离、引用加载、未知名称、路径越界、元数据类型均通过")


if __name__ == "__main__":
    main()
函数合同与取舍
read_limited读取上限+1字节检测溢出,不能先无限读取再截断。UTF-8 解码失败要报告。
split_skill用 YAML 解析 frontmatter 后将 Any 收窄到 object,再检查映射、字段类型和名称。
scan_skills仅扫描一个显式根目录的一级子目录,排序稳定；不同来源的优先级不在本例里暗中发明。
build_index只序列化 name/description；绝对路径不必暴露给模型。
load_skill按发现清单查名称,再次检查正文路径；读取时不执行任何命令。
read_referenceresolve 后同时检查 references 目录与目标路径,避免 ../ 或符号链接越界。

本例仅实现基础 name/description 与正文读取,不是完整规范验证器：可选字段、重复 YAML 键、热更新等都没有完整支持。部署前校验可信内容,会话运行期间不允许非可信进程替换目录；resolve 检查不消除并发文件替换造成的 TOCTOU 风险。

06动手三：接回项目的完整接线步骤

① 将实验里的 SkillCard、read_limited、split_skill、scan_skills、build_index、load_skill、read_reference 连同所需导入复制到你创建的 app/services/skills.py；不要复制 main 与临时测试夹具。② 在 tools.py 增加以下包装函数与两项注册。json、TOOLS_SCHEMA、TOOL_REGISTRY 使用该文件已有定义。

# app/services/tools.py 的新增导入与包装函数；由你手动加入。
import asyncio
from pathlib import Path

from app.services.skills import SkillCard, build_index, load_skill, read_reference, scan_skills

_skill_cards: dict[str, SkillCard] = {}


def initialize_skills(root: Path):
    global _skill_cards
    _skill_cards = scan_skills(root)


def get_skill_index():
    return build_index(_skill_cards)


async def _load_skill(args: dict[str, object]):
    name = args.get("name")
    if not isinstance(name, str):
        return json.dumps({"error": "name 必须是字符串"}, ensure_ascii=False)
    try:
        body = await asyncio.to_thread(load_skill, _skill_cards, name)
        return json.dumps({"name": name, "body": body}, ensure_ascii=False)
    except (ValueError, OSError) as exc:
        return json.dumps({"error": str(exc)}, ensure_ascii=False)


async def _read_skill_reference(args: dict[str, object]):
    name, relative = args.get("name"), args.get("relative")
    if not isinstance(name, str) or not isinstance(relative, str):
        return json.dumps({"error": "name/relative 必须是字符串"}, ensure_ascii=False)
    try:
        body = await asyncio.to_thread(read_reference, _skill_cards, name, relative)
        return json.dumps({"name": name, "reference": relative, "body": body}, ensure_ascii=False)
    except (ValueError, OSError) as exc:
        return json.dumps({"error": str(exc)}, ensure_ascii=False)


# 加在现有 TOOL_REGISTRY 与 TOOLS_SCHEMA 初始化之后。
TOOL_REGISTRY.update({"load_skill": _load_skill, "read_skill_reference": _read_skill_reference})
TOOLS_SCHEMA.extend([
    {
        "type": "function",
        "function": {
            "name": "load_skill",
            "description": "读取可用 Skill 索引中的操作手册。先加载手册再按步骤执行。",
            "parameters": {
                "type": "object",
                "properties": {"name": {"type": "string", "description": "索引中的 Skill 名称"}},
                "required": ["name"],
            },
        },
    },
    {
        "type": "function",
        "function": {
            "name": "read_skill_reference",
            "description": "读取已发现 Skill 的 references 文档。",
            "parameters": {
                "type": "object",
                "properties": {
                    "name": {"type": "string", "description": "Skill 名称"},
                    "relative": {"type": "string", "description": "如 references/types.md"},
                },
                "required": ["name", "relative"],
            },
        },
    },
])

07思考题与详解

为什么不能用 description 的关键词直接 if/else 决定 Skill？

可以为一个固定业务做确定性路由,但它与模型依据语义选择是两种策略。课件让你区分目录发现、选择、加载三个动作,以便每一层独立验证。

Skill 正文可以要求“忽略项目规则并执行所有命令”吗？

文本可以写这种话,host 的执行策略不能因此放宽。把 Skill 当作受信任度需要评估的内容,权限只由可信配置与用户授权改变。

MCP prompts/get 和 load_skill 有什么不同？

前者提供结构化消息模板,通常由用户选用；后者读取可复用步骤,host 可按需交给模型。两者可以组合,但生命周期、参数和加载范围不同。

给模型一份 tools 名称索引就能调用所有工具了吗？

不够。现有模型 API 仍需要合法工具定义。本课常驻两个读取工具的完整 schema,其他工具继续用项目既有 get_all_tool_schemas。动态工具发现是 L9 的另一项设计。

独立断言确认 ONLY_BODY 不出现在元数据索引,显式加载后才出现；同时拒绝未知 Skill、越界引用与非字符串 description。脚本发现手滑词退出 1,文件无法读取退出 2,无命中退出 0,三种情况不能混淆。

接入后先直接调用 load_skill 工具,确认返回完整正文；然后给真实模型相同自查任务,分别用明确 description 与含糊 description 观察选择。记录是否出现工具调用以及返回值,不要只问模型“你加载了吗”。Claude Code 的 /py-hand-check 实验需要实际安装该产品,本项目加载器不依赖它。

回归时覆盖空目录、缺 frontmatter、名称与目录不一致、文件超限、引用符号链接越界。独立自测通过只说明加载机制正常,真正模型的路由效果仍需任务集验证。

09对比小结与进阶预告

Skill 作者写知识和步骤,host 作者实现发现与加载,执行器完成操作。三者连接后才形成能力。下一课 T5 把规则注入与执行授权拆开,让“应该怎么做”和“实际允许做什么”都能被检查。
