01本课目标

只做一件事：让同一个 Agent 回答同一个问题，对比加载 Rules 前后的变化。你会看见规则文件如何变成 system 消息，以及模型如何按规则组织回答。

本课只需要一个短规则文件和一个约 30 行的脚本。代码由你亲手写入；不需要改主项目的 Agent、路由或工具执行器。

02背景回顾：已有 Agent 可以直接复用

项目里的 build_llm_messages 负责组装消息，目前已有 T4 的 Skill 索引 system 消息；run_agent 接收消息，调用模型，并在需要时执行工具。本实验直接使用这两个函数。

仓库根目录的 AGENTS.md 是编程助手的项目约定。你自己的 FastAPI Agent 当前不会自动读取它。本课单独创建 t5_rules.md，放三条容易观察的规则，避免把整份教学项目约定带入实验。

03原理：文件 → 消息 → 模型行为

t5_rules.md 中的文字
    ↓ Python 读取文件
插入 messages，role = system
    ↓ run_agent(messages)
模型看到规则与问题
    ↓
生成符合规则的回答

Rules 的作用来自文本进入了模型上下文。文件名没有魔法；在这个实验里，你把它改名后同步修改路径，效果仍然相同。只把文件放在目录里、没有读取和注入，模型就看不到。

这里由你编写并由宿主加载的规则使用 system 角色。它们与已有 Skill 提示一起发给模型；本实验选择互不冲突的内容，不讨论多层目录的优先级。

04动手实现：两个小文件

步骤 1 · 写三条规则

由你创建 scripts/t5_rules.md：

你是一位中文 Agent 开发老师。
每次回答的第一行必须是：规则已加载
接下来只用两个编号条目解释，每条一句话，不调用工具。

固定首行是观察标记；两个条目是输出格式；不调用工具是行为要求。它们都由模型理解并尝试遵循。

步骤 2 · 运行同一个 Agent 两次

由你将 scripts/t5_rules_lab.py 调整为以下完整内容。原版的 Gate、审批、临时目录和审计逻辑在这个实验里都不需要。

"""T5：对比同一个 Agent 加载 Rules 前后的回答。"""

import asyncio
from pathlib import Path

from app.services.agent import build_llm_messages, run_agent

RULES_FILE = Path(__file__).with_name("t5_rules.md")
QUESTION = "什么是 Agent？"


async def ask(use_rules: bool):
    # 每次创建新上下文，保留项目已有的 Skill system 消息。
    messages = build_llm_messages([])
    rules = RULES_FILE.read_text(encoding="utf-8") if use_rules else ""
    if rules:
        messages.insert(0, {"role": "system", "content": rules})

    messages.append({"role": "user", "content": QUESTION})
    print("\n=== 加载 Rules ===" if use_rules else "\n=== 不加载 Rules ===")
    print("本次额外规则：", rules or "无")
    answer, _ = await run_agent(messages)
    print(answer)


async def main():
    await ask(False)
    await ask(True)


if __name__ == "__main__":
    asyncio.run(main())

read_text 读取规则；messages.insert 把规则加入上下文；run_agent 仍使用现有执行循环。SDK 类型由已有函数传递推导，脚本不用额外导入 OpenAI 类型，也不用写 cast。

两次都创建全新 messages，防止第一次回答影响第二次。这里的“不加载”指不加载本课的额外 Rules，项目原有的 Skill 提示仍保留。

05验证实验：先看变化，再改规则

前置：项目依赖已安装，.env 已配置当前 DeepSeek 模型所需的地址、密钥与模型名。项目仍使用 ark_* / ARK_* 历史配置名。本实验直接调用 Agent，不启动 FastAPI lifespan，不加载 MCP 或 Skill 文件；问题本身不需要工具和数据库查询，但导入配置仍要求有效的 DATABASE_URL。

uv run python -m ruff check scripts/t5_rules_lab.py
uv run python -m mypy --follow-imports=silent --check-untyped-defs scripts/t5_rules_lab.py
uv run python -m scripts.t5_rules_lab

最后一条命令会调用真实模型，产生 API 用量。第一组回答的形式不固定；第二组预期以“规则已加载”开头，随后只有两个编号条目。解释内容不要求逐字一致。

  1. 观察注入：终端打印的“本次额外规则”应与文件内容一致。
  2. 观察行为：检查回答首行和条目数，而不是只看模型是否声称遵守了规则。
  3. 修改规则：把首行改为“我是极简老师”，条目数改成三个，再运行。回答应随规则变化。
  4. 移除注入：临时注释 messages.insert 那一行再运行。即使程序读到了规则，它们也不会进入模型上下文。完成后恢复。

找不到文件时，检查 t5_rules.md 是否与脚本同目录；认证或模型名错误时，先检查现有模型配置。若规则打印正确但输出不符合要求，这是模型遵循情况，需要记录实际回答，不能把提示词当成确定性校验。

06思考题与详解

Rules 和普通 prompt 是什么关系？

在本实验中，Rules 是保存在文件里的长期约定，读取后成为 system prompt 的一部分。用户这次提出的问题则放在 user 消息里。加载方式与消息角色由宿主程序决定。

为什么文件存在，但 Agent 没遵守？

先确认文件有没有被读到，再确认文本有没有加入实际发送的 messages。即使两步都正确，模型仍可能不完全遵循规则；需要检查真实输出。

写“不调用工具”，就能保证工具永远不执行吗？

不能。这句规则影响模型选择，但当前 execute_tool 没因此多出权限检查。要保证某个工具不能运行，需要在执行前用程序拦截。这里先理解两者区别，不实现权限系统。

07对比小结

操作发生了什么
只创建规则文件磁盘上有文本，模型尚不可见。
读取文件但不注入Python 拿到了文本，模型仍不可见。
作为 system 消息发送模型获得规则，可以据此调整回答或工具选择。
工具前的程序检查控制实际执行，是后续的执行边界话题。

08进阶预告：正式接入放在哪里

体验完成后，如果要让每次聊天都使用规则，可以在 build_llm_messages 组装 system 内容时加入规则文本，并保留已有的 Skill 索引。这样非流式和流式 Agent 都能收到规则，不需要复制两份加载逻辑。

本课到“规则文本改变 Agent 行为”为止。审批与任务暂停/恢复放到 L12；提示词注入和工具权限放到 L15。
