01本课目标

看清规则从文件到模型的路径,并用一个最小闸门证明：未经批准时底层函数不会被执行。掌握审批与参数快照绑定、一次性使用、审计回调和默认拒绝。

练习方式本课代码是供你亲手输入的教学内容。Agent 维护 doc/ 课件；app/、scripts/ 和配置由你自己创建或修改。先运行独立实验，再按接入说明修改主项目。代码中的演示工具与目录均会明确标注，不把实验结果当作模型端到端验收。

02背景回顾：本项目的规则与执行入口

仓库 AGENTS.md 是共用规则正文,CLAUDE.md 只通过 @AGENTS.md 导入。这个机制服务于你使用的编程助手,不会自动传给你自己的 FastAPI Agent。你的 Agent 当前从 build_llm_messages 装载聊天历史,工具执行统一经过 execute_tool。

编程助手的项目规则 → 约束帮你学习的助手
你自己的 Agent → 必须自己实现规则加载、消息注入和执行检查

本课选一个明确的教学合同：从项目根目录到指定目标文件父目录,依次读各层 AGENTS.md；不自动探索任意全盘路径,不模拟所有产品的优先级,也不解析 CLAUDE.md 的 @import。这样本项目的共享正文只读一次。规则目录要由可信 host 配置。

03原理：文本约束、执行策略、Hook

机制何时发生可以保证什么
规则文本模型请求前加入上下文让模型看见约定；仍需观察是否遵循。
执行策略调用底层工具之前阻止未获许可的回调执行；必须覆盖所有执行路径。
审批先暂停,用户作决定后恢复绑定展示给用户的具体操作；不是模型自行填 approved=true。
Hook工具前后或其他事件触发按其实现做校验/审计；不是所有产品事件都能阻断。
沙箱操作系统/运行时层面限制文件/网络等实际能力；与提示词和工具名规则是不同层。

自然语言规则的冲突不能简单靠“最后一个文件覆盖”来可靠解决。下面保留顺序与来源,让人能检查冲突,不会用字符串拼接假装理解所有规则。对执行策略可以给出明确算法：未知默认拒绝,只读样例允许,写入样例请求审批。

审批决定必须由可信 UI/接口传来,鉴别用户与会话。这里的 review 是 host 内部方法,不注册成模型工具。审批 id 对应已验证且冻结的参数快照,批准后不能换参数再执行。

核对依据：Claude Code 规则与记忆 · Path.resolve

04动手实现：规则加载 + 最小执行闸门

创建 scripts/t5_rules_lab.py。read_note、save_note、erase_note 是实验里的工具名,没有加入你项目。fake_tool 只记录调用并返回 JSON,没有真实写磁盘。这让你能用“执行次数”验证权限,不依赖模型是否口头表示遵守。

由你创建：scripts/t5_rules_lab.py

"""T5:规则加载与执行闸门,用户抄入 scripts/t5_rules_lab.py。"""

import asyncio
import json
from collections.abc import Awaitable, Callable
from dataclasses import dataclass
from pathlib import Path
from tempfile import TemporaryDirectory
from uuid import uuid4

from pydantic import BaseModel, ConfigDict, ValidationError


@dataclass(frozen=True)
class RuleText:
    source: str
    content: str


def load_rules(root: Path, target_file: Path):
    """教学版约定:项目根到目标文件父目录,依次加载 AGENTS.md。"""
    root = root.resolve(strict=True)
    target = target_file.resolve(strict=True)
    if not target.is_relative_to(root) or not target.is_file():
        raise ValueError("目标文件不在项目内")
    folders = [root]
    current = root
    for part in target.parent.relative_to(root).parts:
        current /= part
        folders.append(current)
    rules: list[RuleText] = []
    total = 0
    for folder in folders:
        path = folder / "AGENTS.md"
        if not path.exists():
            continue
        resolved = path.resolve(strict=True)
        if not resolved.is_relative_to(root):
            raise ValueError("规则文件越出项目")
        with resolved.open("rb") as stream:
            raw = stream.read(16_385)
        total += len(raw)
        if len(raw) > 16_384 or total > 32_768:
            raise ValueError("规则超出预算,请人工精简")
        rules.append(RuleText(str(path.relative_to(root)), raw.decode("utf-8")))
    return rules


def rules_to_text(rules: list[RuleText]):
    # 保留来源与顺序,便于人工排查冲突。程序不猜测自然语言的覆盖关系。
    return "\n\n".join(f"【来源:{rule.source}】\n{rule.content}" for rule in rules)


class NoteArgs(BaseModel):
    model_config = ConfigDict(strict=True, extra="forbid")
    text: str


@dataclass(frozen=True)
class PendingCall:
    name: str
    arguments_json: str  # 审批绑定规范化后的参数快照。


ToolFn = Callable[[str, dict[str, object]], Awaitable[str]]


class Gate:
    def __init__(self, dispatch: ToolFn):
        self.dispatch = dispatch
        self.pending: dict[str, PendingCall] = {}
        self.audit: list[str] = []

    async def request(self, name: str, arguments_json: str):
        # 默认拒绝未知工具。模型不能通过参数新增权限。
        if name not in {"read_note", "save_note"}:
            self.audit.append(f"deny:{name}")
            return {"error": "工具未获授权"}
        try:
            args = NoteArgs.model_validate_json(arguments_json)
        except ValidationError:
            return {"error": "参数必须仅包含字符串 text"}
        if name == "save_note":
            call_id = uuid4().hex
            self.pending[call_id] = PendingCall(name, args.model_dump_json())
            self.audit.append(f"ask:{name}")
            return {"approval_required": call_id, "name": name, "arguments": args.model_dump()}
        return {"result": await self._execute(name, args)}

    async def review(self, call_id: str, allow: bool):
        """只由可信 host 的用户操作调用,绝不作为模型工具注册。"""
        pending = self.pending.pop(call_id, None)
        if pending is None:
            return {"error": "审批不存在或已使用"}
        if not allow:
            self.audit.append(f"rejected:{pending.name}")
            return {"error": "用户拒绝执行"}
        # 执行已展示并批准的快照,不接收模型重传的另一份参数。
        args = NoteArgs.model_validate_json(pending.arguments_json)
        return {"result": await self._execute(pending.name, args)}

    async def _execute(self, name: str, args: NoteArgs):
        self.audit.append(f"before:{name}")
        try:
            result = await self.dispatch(name, {"text": args.text})
        except Exception:
            self.audit.append(f"failed:{name}")
            raise  # 取消/业务错误不能被 after 事件伪装成成功。
        self.audit.append(f"after:{name}")
        return result


async def main():
    with TemporaryDirectory() as tmp:
        root = Path(tmp)
        (root / "app").mkdir()
        (root / "AGENTS.md").write_text("全程中文。", encoding="utf-8")
        (root / "app/AGENTS.md").write_text("此目录的参数必须标注类型。", encoding="utf-8")
        target = root / "app/demo.py"
        target.write_text("", encoding="utf-8")
        loaded = load_rules(root, target)
        assert [r.source for r in loaded] == ["AGENTS.md", "app/AGENTS.md"]
        assert "全程中文" in rules_to_text(loaded)

    executed: list[str] = []

    async def fake_tool(name: str, args: dict[str, object]):
        executed.append(name)
        return json.dumps(args, ensure_ascii=False)

    gate = Gate(fake_tool)
    denied = await gate.request("erase_note", '{"text":"x"}')
    assert "error" in denied and executed == []
    bad = await gate.request("save_note", '{"text":"x","approved":true}')
    assert "error" in bad and executed == []
    await gate.request("read_note", '{"text":"x"}')
    requested = await gate.request("save_note", '{"text":"固定快照"}')
    assert executed == ["read_note"]
    call_id = requested["approval_required"]
    assert isinstance(call_id, str)
    await gate.review(call_id, True)  # 测试里模拟可信用户点击;产品不可自动批准。
    assert executed == ["read_note", "save_note"]
    assert "error" in await gate.review(call_id, True)
    rejected = await gate.request("save_note", '{"text":"y"}')
    reject_id = rejected["approval_required"]
    assert isinstance(reject_id, str)
    await gate.review(reject_id, False)
    assert executed == ["read_note", "save_note"]
    print("T5:层级规则、默认拒绝、禁止伪造批准、审批前不执行、一次性批准与拒绝均通过")


if __name__ == "__main__":
    asyncio.run(main())
代码位置解释
load_rules根目录与目标文件都 resolve；只沿目标路径祖先加载,每个文件和总量都有预算。
rules_to_text附来源后拼接；只生成文本,没有执行权限副作用。
NoteArgsstrict=True, extra=forbid；模型传 approved 字段会失败,不是悄悄忽略。
Gate.request策略先判断工具名,再校验参数；save_note 只存 pending,不会运行 dispatch。
PendingCall保存名字与规范化 JSON,避免批准展示 A 后执行 B。
Gate.reviewpop 使审批只能用一次；拒绝不调用执行器。
_executebefore/after 是实际回调事件,只在 dispatch 成功后记 after。

为什么不用一整套权限规则 DSL？因为这个阶段要看清调用时机与信任边界。等工具类型和产品交互确定,再引入更细的路径、租户或操作范围策略。当前 pending 是进程内内存,进程退出会丢失,还没有 TTL、身份验证与并发原子性,不能直接拿去做多 worker 生产审批。

05接回 Agent：文本在哪,闸门在哪

把 RuleText、load_rules、rules_to_text 和所需导入复制到你创建的 app/services/rules.py,再加入以下缓存入口。启动时加载一次,内容变化后重启。

_active_rules = ""


def initialize_rules(root: Path, target_file: Path):
    global _active_rules
    _active_rules = rules_to_text(load_rules(root, target_file))


def get_rules_text():
    return _active_rules

main.py 新增导入,并在 lifespan 的 yield 前初始化。这里用固定 agent.py 演示目录继承范围；文件编辑型 Agent 应由可信 host 根据任务目标选择规则,不开放任意磁盘路径。

# lifespan 的 yield 前执行
project_root = Path(__file__).resolve().parents[1]

模型 tool_call
→ JSON 解析 + 参数形状验证
→ host 策略检查
   ├─ allow → execute_tool / 底层 dispatch → 结果
   ├─ deny  → 错误结果,执行次数不增加
   └─ ask   → 保持暂停,等可信用户操作 → 执行原快照或拒绝

闸门要覆盖内置与 MCP 两条分支,而不是只包 TOOL_REGISTRY。否则同名工具经 _mcp_schemas 分发就绕过检查。非流式与流式 loop 都要走同一入口。

接入审批不能只把 {approval_required: ...} 当成普通 tool result 然后立即让模型继续循环：那样没有真正暂停任务。产品接入要保存待执行的 tool_call_id、参数和剩余执行位置,等待审批后再恢复,并且只写一个对应的最终 tool 结果。SSE 可发 approval_required 事件,但事件合同、会话互斥释放方式、审批期间的超时与重连都要在 L12 一起设计。

因此本课在独立实验里实现完整 request → review → dispatch 流程；主项目先接可直接完成的 allow/deny,审批的持久恢复放到 L12。进程内 pending 不是分布式任务系统。读取规则也不能长时间占着 AsyncSession,连接只在数据库读写时使用。

06动手接线：先把 allow/deny 放进现有执行入口

在 tools.py 把原 execute_tool 改名为 _execute_tool_unchecked,原函数体保留。然后加入下列同名入口。json 使用已有导入,两个 agent loop 的导入名也不变。工具新增后由开发者显式更新白名单,模型不能修改这个集合。

ALLOWED_TOOL_NAMES = frozenset({
    "get_current_weather", "get_city_time", "search_knowledge_base",
    "text_stats", "load_skill", "read_skill_reference",
})


async def execute_tool(name: str, arguments_json: str):
    if name not in ALLOWED_TOOL_NAMES:
        return json.dumps({"error": f"工具未获授权:{name}"}, ensure_ascii=False)
    return await _execute_tool_unchecked(name, arguments_json)

这一入口先拦工具名,再由旧执行器解析参数和分发,因此内置与 MCP 都经过检查。尚未注册的白名单工具仍由旧执行器返回“未知工具”。自家 L7 server 内调用 execute_tool 时也会经过它。若 MCP 能用同名工具覆盖但改变行为,还要在可信注册阶段绑定来源和权限,只认名称不足以覆盖这种风险。

先把 search_knowledge_base 临时移出白名单,直接调用与聊天调用均应被拒绝,且检索侧没有执行；恢复后再验证正常调用。这个实验无需让模型理解禁止规则就能证明闸门生效。

07代码审视：把例外写进明确合同

项目“Agent 不改源码,课件可改”的规则有清晰例外。若将其实现成文件工具策略,检查规范化后的目标是否在允许根目录内,而不是判断字符串里有没有 doc/。符号链接也必须检查,真正防止竞争条件需更严格的文件操作方式或沙箱。

read_note/save_note 这套按名字的策略只覆盖实验回调,并不自动限制任意 shell 或 server 内部的二次操作。一个可执行任意命令的 Bash 工具足以绕过粗粒度工具名许可,所以实际工具设计也应保持明确的业务输入范围。

Hook 的 after 事件可以做审计,但审计失败是否使业务返回失败需要提前定义。业务已经完成后,记录日志失败不代表操作没有发生；不能在错误处理里盲目重试写入。审批通过同样不保证执行必然成功,执行失败仍要报告真实结果。

08思考题与详解

为什么把 deny 规则写成一句 system prompt 不够？

system 文本影响模型生成,但没有在 Python 执行前检查就没有程序层阻断。用 fake_tool 的计数能直接检验这一点。

为什么批准后不能让模型重新提交参数？

用户批准的是已展示的具体操作。若允许替换参数,批准 A 可能执行 B。pending 保存不可变 JSON 快照,review 只消费该快照。

能把 allow=True 直接作为 tool 参数吗？

不能把它当作权限来源。模型能生成该字段,不代表用户已批准。可信 host 的审批入口必须与模型工具入口分开。

为什么拒绝时不抛一个异常终止整个聊天？

可以用稳定错误结果让模型知道操作未执行。但 host 必须明确拒绝和业务失败,不能伪造成功。协议/连接损坏等失败则需要上层决定终止或恢复。

观察根规则与子目录规则的加载顺序；erase_note 被默认拒绝；传 approved 字段不改变权限；save_note 请求后 executed 不变；批准一次后只增加一次；重复批准和拒绝不会再执行。

扩展实验：在 fake_tool 中针对某个 text 抛 RuntimeError,核对失败被记录且没有 after 成功事件；让目标文件位于项目外,核对规则加载拒绝；给规则文件写超过预算的文本,核对没有静默裁掉后面的关键约束。

模型实验：给规则加入“回答使用中文”,观察真实模型是否遵循；再要求调用被拒绝的工具,看执行次数保持不变。前者测试模型行为,后者测试程序权限,两者不能用同一条“模型说已遵守”作为证据。

10对比小结与进阶预告

规则文本负责表达意图,执行策略负责控制回调,审批负责取得具体操作的授权,Hook 提供事件点。L12 会补齐长任务暂停/恢复与多 worker 审批,L15 再做恶意工具输出和引用文档中的注入攻防。
