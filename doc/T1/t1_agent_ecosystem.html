01本课目标

能够沿着一次请求说清：谁提供能力、谁加载知识、谁作出调用决定、谁真正执行、谁可以拒绝执行。用已有 L4～L7 代码作基座，不引入 Agent 框架。

练习方式本课代码是供你亲手输入的教学内容。Agent 维护 doc/ 课件；app/、scripts/ 和配置由你自己创建或修改。先运行独立实验，再按接入说明修改主项目。代码中的演示工具与目录均会明确标注，不把实验结果当作模型端到端验收。

02背景回顾：现有项目的调用链

routers/chats.py
  → build_llm_messages(history)
  → run_agent / run_agent_stream
  → get_all_tool_schemas → llm_client
  → 模型返回 tool_call(name, arguments)
  → execute_tool → 内置函数 / McpClient.call_tool
  → 工具结果绑定 tool_call_id → 下一轮模型
  → new_stored 整轮轨迹由 router 写库

SDK 类型集中在 services/llm/ 与 agent.py；tools.py 接收工具名与 JSON 参数字符串，返回字符串。跨进程边界仍要校验输入形状。轨迹写库是整轮语义单元，不能因为加一项扩展就把数据库连接包到模型等待外面。

03原理：四种机制各自负责什么

主题入口与产物对 Agent 的作用实现所在位置
CLI参数列表 → 进程 → stdout/stderr/退出码执行一项具体操作工具执行器
MCP握手、发现、请求/响应统一访问 tools/resources/promptshost 内的 client 与独立 server
SKILL元数据索引 → 操作手册 → 引用/脚本组织可复用的操作知识上下文构造器与按需读取工具
Rules适用规则文本 + 执行策略告诉模型约定,在执行边界检查权限上下文层与执行闸门分别实现

这些机制可以组合：Skill 写“先读使用说明，再检索知识库”；host 从 MCP resource 读取说明；模型选择检索 tool；server 内部可以调用 CLI；真正执行前由 host 检查策略。MCP 不负责决定全部内容何时进入模型，Skill 文件也不会自行执行。

04动手：沿一次调用定位边界

rg -n 'build_llm_messages|run_agent|append_messages' app/routers/chats.py
rg -n 'get_all_tool_schemas|execute_tool|tool_call_id' app/services/agent.py
rg -n 'register_mcp_tools|_mcp_call|TOOL_REGISTRY' app/services/tools.py
rg -n 'start|tools/list|tools/call|_recv' app/services/mcp/client.py

按顺序打开命中的函数,写下每一步输入和输出。尤其区分模型提出调用与 Python 真正执行：生成 tool_calls 不等于操作已完成。再检查两种 agent loop，确认新的能力不会只接到非流式路径。

05思考题与详解

一个 Skill 能否直接替代 execute_tool？

不能。手册可以描述步骤,但执行器负责实际 I/O、参数检查和结果。把说明放进上下文不会自动获得程序权限。

为什么不把四课合成一个“大插件课”？

四者的故障边界不同。CLI 看进程与输出,MCP 看协议与连接,Skill 看发现和上下文,Rules 看规则来源与执行授权。分开实验更容易定位失败。

模型没有遵守规则,是否代表规则文件没加载？

不一定。先验证加载结果和注入位置,再观察模型遵循情况。规则文本影响生成行为,执行闸门则直接决定回调会不会运行。

06验证实验：用可观测结果说明能力

课件最小实验验收证据
T2实际启动子进程并制造失败退出码、输出、超时和取消结果
T3stdio 传输三类原语请求 id 对应,协议错误与业务错误可区分
T4扫描元数据再读取正文索引无正文标记,显式加载后才有
T5先请求再人工决定审批批准前执行次数不增加,拒绝后仍不执行

独立实验不用真实模型,便于重复验证机制。接入 FastAPI 后还需真实模型与 SSE 验证,两类证据分别记录。

07对比小结：实现时抓住三个问题

每个扩展都要说明它的数据合同、生命周期和失败出口。只有文本约定不足以保证外部操作安全；只有协议成功也不足以证明业务成功；只有文件存在更不等于它已进入模型上下文。

周边概念与四课的联系
子 Agent独立 messages 与循环,在 L11 深入；可加载自己的 Skill 与规则。
Hook特定事件上的回调；T5 用执行前后回调演示,具体产品的事件与阻断能力各异。
插件分发单元,可组合 Skill、MCP 和其他配置；安装与运行权限是两回事。
