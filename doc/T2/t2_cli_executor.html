01本课目标

亲手实现一个异步 CLI 执行器：传参不经 shell,同时读取 stdout/stderr,限制保留的输出,区分启动失败、非零退出、超时与取消。最后把它映射到 TOOL_REGISTRY。

练习方式本课代码是供你亲手输入的教学内容。Agent 维护 doc/ 课件；app/、scripts/ 和配置由你自己创建或修改。先运行独立实验，再按接入说明修改主项目。代码中的演示工具与目录均会明确标注，不把实验结果当作模型端到端验收。

02背景回顾：从 execute_tool 到进程

现有 app/services/tools.py 的 execute_tool(name, arguments_json) 解析 JSON,检查必填键,优先分发 MCP,否则查 TOOL_REGISTRY。ToolFunc 的合同是异步函数接收 dict[str, object]、返回 str。新增 CLI 工具可以保持此合同,在内部启动程序。

模型参数 text → _text_stats / text_stats → run_cli(argv)
→ Python 子进程 → 机器结果 stdout + 诊断 stderr + returncode
→ 业务适配器产生 JSON 字符串 → 原 tool_call_id 的 tool 消息

现有 _validate_required 只检查键是否存在,不检查值的类型。示例会在读取 text 时用 isinstance 收窄。工具名由 host 注册,可执行文件和脚本路径也由 host 固定,不让模型传任意命令字符串。

03原理：进程合同与资源生命周期

选择原因容易误解之处
create_subprocess_exec(*argv)每个参数是独立字符串,不会把分号当作 shell 语句它不等于沙箱；被调用的程序仍有自身权限与参数语义。
stdout/stderr 同时读取任一管道写满都可能阻塞子进程await proc.wait() 加一根未排空的 PIPE 可能僵住。
保留上限 + 继续排空控制内存,同时允许子进程退出StreamReader 的 limit 是缓冲阈值,不是总输出预算。
timeout + finally 回收超时或取消不遗留正在运行的直接子进程取消本身不是业务成功,不应被转成一段空结果。
退出码与业务结果分开0 是进程层成功;业务 JSON 仍可能报告失败非零退出时 stderr 有诊断价值,不可只返回 stdout。

本例只管理直接子进程,要求演示 worker 不派生后代。真实 CLI 会启动其他进程时,需按操作系统设计进程组终止;不要把本例宣称为完整进程树监管器。输出截断也不等于停止工作量,持续输出还要靠运行时预算控制。

核对依据：Python 3.13 异步子进程

04动手实现：一份可独立运行的实验

步骤一：创建 scripts/t2_cli_lab.py,完整代码如下。同一文件有 host 和 worker 两个入口：正常运行执行断言；加 --worker 则作为子进程处理参数。sys.executable 保证使用同一个 Python 环境。

由你创建：scripts/t2_cli_lab.py

"""T2:由用户抄入 scripts/t2_cli_lab.py;本文件不依赖模型或数据库。"""

import argparse
import asyncio
import json
import sys
import time
from contextlib import suppress
from dataclasses import asdict, dataclass
from pathlib import Path


@dataclass(frozen=True)
class CliResult:
    returncode: int | None
    stdout: str
    stderr: str
    truncated: bool
    error: str | None = None


async def read_bounded(reader: asyncio.StreamReader, keep_bytes: int):
    """只保留前 keep_bytes 字节,但继续排空管道,避免子进程卡在写入。"""
    saved = bytearray()
    total = 0
    while chunk := await reader.read(4096):
        total += len(chunk)
        saved.extend(chunk[: max(0, keep_bytes - len(saved))])
    # 截断可能落在一个汉字中间,replace 显式替换残缺字符。
    return saved.decode("utf-8", errors="replace"), total > keep_bytes


async def run_cli(argv: list[str], cwd: Path, timeout: float = 2.0, keep_bytes: int = 4096):
    if not argv or timeout <= 0 or keep_bytes < 0:
        raise ValueError("argv 不能为空,timeout 必须为正,keep_bytes 不能为负")
    try:
        proc = await asyncio.create_subprocess_exec(
            *argv,
            cwd=cwd,
            stdin=asyncio.subprocess.DEVNULL,
            stdout=asyncio.subprocess.PIPE,
            stderr=asyncio.subprocess.PIPE,
        )
    except OSError as exc:
        return CliResult(None, "", "", False, f"启动失败:{exc}")
    assert proc.stdout is not None and proc.stderr is not None
    # 两根管道同时排空。只读 stdout,可能被写满的 stderr 反向阻塞。
    out_task = asyncio.create_task(read_bounded(proc.stdout, keep_bytes))
    err_task = asyncio.create_task(read_bounded(proc.stderr, keep_bytes))
    error: str | None = None
    try:
        async with asyncio.timeout(timeout):
            await proc.wait()
            out, out_cut = await out_task
            err, err_cut = await err_task
    except TimeoutError:
        error = "执行超时"
    finally:
        # 超时或上层取消都要回收子进程。取消异常不会变成成功结果。
        if proc.returncode is None:
            with suppress(ProcessLookupError):
                proc.kill()
        await proc.wait()
        for task in (out_task, err_task):
            if not task.done():
                task.cancel()
        await asyncio.gather(out_task, err_task, return_exceptions=True)
    if error is not None:
        return CliResult(proc.returncode, "", "", False, error)
    return CliResult(proc.returncode, out, err, out_cut or err_cut)


def worker():
    """独立子进程:stdout 只给机器结果,stderr 给诊断。mode 仅用于故障实验。"""
    parser = argparse.ArgumentParser()
    parser.add_argument("--mode", choices=["count", "fail", "flood", "wait"], default="count")
    parser.add_argument("text")
    args = parser.parse_args(sys.argv[2:])
    if args.mode == "fail":
        print("模拟业务失败", file=sys.stderr)
        raise SystemExit(3)
    if args.mode == "wait":
        time.sleep(5)  # 真正制造慢命令,仅用于超时/取消实验。
    if args.mode == "flood":
        print("x" * 100_000)
        print("y" * 100_000, file=sys.stderr)
        return
    print(json.dumps({"text": args.text, "characters": len(args.text)}, ensure_ascii=False))


async def text_stats(args: dict[str, object]):
    """与 TOOL_REGISTRY 的 ToolFunc 同形:业务参数进,JSON 字符串出。"""
    value = args.get("text")
    if not isinstance(value, str):
        return json.dumps({"error": "text 必须是字符串"}, ensure_ascii=False)
    result = await run_cli(
        [sys.executable, str(Path(__file__).resolve()), "--worker", "--", value],
        Path(__file__).resolve().parent,
    )
    if result.error or result.returncode != 0 or result.truncated:
        return json.dumps({"error": "CLI 未完整成功", "detail": asdict(result)}, ensure_ascii=False)
    # 此处先交回业务 JSON;消费其中字段的一侧仍应使用 Pydantic 验证。
    return result.stdout


async def main():
    base = [sys.executable, str(Path(__file__).resolve()), "--worker"]
    cwd = Path.cwd()
    ok = await run_cli([*base, "--", "你好; echo unsafe"], cwd)
    assert ok.returncode == 0 and "你好; echo unsafe" in ok.stdout
    fail = await run_cli([*base, "--mode", "fail", "a"], cwd)
    assert fail.returncode == 3 and "模拟业务失败" in fail.stderr
    flood = await run_cli([*base, "--mode", "flood", "a"], cwd, keep_bytes=64)
    assert flood.truncated and len(flood.stdout.encode()) == 64
    slow = await run_cli([*base, "--mode", "wait", "a"], cwd, timeout=0.2)
    assert slow.error == "执行超时"
    missing = await run_cli(["/definitely-not-an-installed-command"], cwd)
    assert missing.error is not None and missing.returncode is None
    task = asyncio.create_task(run_cli([*base, "--mode", "wait", "a"], cwd))
    await asyncio.sleep(0.05)  # 测试时让子进程启动;产品路径不靠延时排序。
    task.cancel()
    try:
        await task
    except asyncio.CancelledError:
        pass
    else:
        raise AssertionError("取消必须传回调用方")
    assert "error" in await text_stats({"text": 123})
    print("T2:成功、非零退出、输出限制、超时、启动失败、取消、类型错误均通过")


if __name__ == "__main__":
    if len(sys.argv) > 1 and sys.argv[1] == "--worker":
        worker()
    else:
        asyncio.run(main())
函数读代码时关注什么
read_bounded总字节数与保留字节数分开；即使已保留足够内容,循环仍继续排空。
run_cli输入验证在启动前；OSError 是启动失败；finally 始终等待进程回收。
worker真实 CLI 可以带登录态或交互提示。本例禁用 stdin,只演示可脚本化的机器接口。
text_stats把 CliResult 适配回工具字符串；截断结果不当作完整 JSON 解析。
main每条断言都对应一个行为,不用模型打分判断进程是否被正确处理。

步骤二：理解异常出口。TimeoutError 在执行器内转成明确结果；CancelledError 穿过 finally 返回调用方。此处只演示单次取消,服务关闭时还需确保清理任务不被反复取消。

步骤三：接回项目时,把执行器部分移到 app/services/cli_executor.py,把 worker 单独保留为受控脚本,并为 tools.py 写一个异步适配函数。先只用本实验测试,再执行下面的项目接入练习。

05接回工具注册表：具体改动位置

若先直接复用实验文件,可以在 tools.py 导入它的 text_stats 作为过渡,不引入 SDK。下列片段由你加入现有定义之后；最终工程化时再把通用执行器移到 services。

from scripts.t2_cli_lab import text_stats

TOOL_REGISTRY["text_stats"] = text_stats
TOOLS_SCHEMA.append({
    "type": "function",
    "function": {
        "name": "text_stats",
        "description": "精确计算用户提供文本的字符数。",
        "parameters": {
            "type": "object",
            "properties": {"text": {"type": "string", "description": "要统计的原文"}},
            "required": ["text"],
        },
    },
})

run_agent 与 run_agent_stream 都已经经过 execute_tool,这一步不需要复制两套 subprocess 逻辑。工具名称不能与 MCP 同名,否则现有优先级会转向 MCP。正式接入还应把 stdout JSON 用 Pydantic 建模,避免未来更换 CLI 后返回非 JSON 或字段漂移。

为什么练习里不让模型传 executable？因为选择可执行程序属于 host 提供能力的范围；模型只填 text 业务参数。即使用 exec 而不用 shell,开放任意程序路径仍然是开放执行权限。

06思考题与详解

为什么超时后不能只 return 一个 error？

父协程返回并不会让子进程自动结束。finally 必须终止仍在运行的进程并 wait,否则程序继续耗资源。

为什么输出保留满了以后还继续 read？

如果不读,子进程可能卡在写满的管道上,无法退出。另一种可选设计是达到上限立即终止子进程,但要把这种终止定义为失败,不能当成正常完成。

为什么不把一个 shell 命令整体拼成字符串？

模型文本一旦被 shell 解释,引号、分号、重定向都会改变行为。argv 保留数据边界;-- 还避免文本被 argparse 当作选项。
