01本课目标：让 Agent 真正调用一次 CLI

本课围绕一句请求展开：“请用工具统计‘你好世界’有多少个字符。”学完后，你能指出模型在哪一步提出请求、Python 宿主在哪一步启动程序，以及 CLI 的输出怎样成为下一轮模型的输入。然后再处理超时、输出预算和取消。

学习边界以下文件与改动均由你亲手写入。课件只提供完整示例与验证命令。已有 scripts/t2_cli_lab.py 可以保留作旧实验；新流程不导入它，也不依赖它。所有命令默认在项目根目录执行。

02背景回顾：模型、Agent 宿主与 CLI 各做什么

L4 的 function calling 让模型生成工具名称与 JSON 参数；L5 的 agentic loop 负责执行请求，再把结果交回模型。模型本身没有操作系统进程句柄。这里把运行 agent.py、tools.py 的 Python 程序称为“宿主”；Agent 系统由模型、宿主循环和可用工具共同组成。

用户：请用工具统计“你好世界”
  ↓
模型 ← 宿主发送 messages + 工具说明 TOOLS_SCHEMA
  ↓ 返回 tool_calls：text_stats({"text":"你好世界"})
宿主 agent.py → execute_tool → tools.py 的 _text_stats
  ↓ 业务参数变成 argv，调用 run_cli
执行器 → 操作系统创建独立进程【真正的 CLI 调用边界】
  ↓ python scripts/text_stats_cli.py -- "你好世界"
CLI → stdout: {"characters":4,"pid":子进程编号} → 退出
  ↓ 执行器收集 stdout / stderr / 退出码
适配器校验 JSON → Agent 追加 role="tool"、原 tool_call_id
  ↓ 再次请求模型
模型：这段文本有 4 个 Unicode 码点。

上面需要至少两次模型请求：第一次拿到工具调用，第二次把结果交回模型生成回答。CLI 在两次请求之间运行。示例中的 pid 用于观察进程边界；它是教学字段，不代表真实业务必须返回进程号。

部件知道什么如何连接下一层
模型text_stats 的说明与 text 参数输出工具调用请求
agent.py（已有）工具名称、参数、调用 ID调用 execute_tool 并回传结果
tools.py 适配器参数规则、CLI 路径与输出合同import 执行器，传入 argv
cli_executor.py进程、管道、超时subprocess 启动程序
text_stats_cli.py命令行参数与统计逻辑stdout 输出 JSON

import 是加载进程内的模块；subprocess 是启动另一个程序。tools.py 可以 import 执行器，但不会 import text_stats_cli.py。即使以后把 CLI 换成 Go 可执行文件，这条边界仍成立。

03原理：专用工具怎样映射成命令

CLI 是程序暴露给命令行调用者的接口，既能由人在终端使用，也能由另一个程序启动。它不需要知道调用方是不是 Agent。这里选择自己写一个极小 CLI，使输入与输出都能看清；重点不是统计功能有多复杂。

# 人在终端输入的等价命令
python scripts/text_stats_cli.py -- "你好世界"

# 宿主传给执行器的 argv（这是列表，不是 shell 字符串）
[sys.executable, str(script), "--", text]

sys.executable 指向当前 Python 解释器；script 是宿主固定的绝对路径；“--”结束 argparse 的选项解析，后面的 --help 也会当作文本。create_subprocess_exec(*argv) 按独立参数启动程序，不经过 shell；分号不会在这里变成另一条命令。它并不提供权限沙箱。

本课采用“专用工具”：模型只填 text，宿主决定执行哪个程序。另一种方式是给模型 run_command 工具，让模型填写命令；那需要更广的命令授权与工作目录控制。两者都能连接 Agent 与 CLI，本课先把前者走通，T5 再讨论执行边界。

04动手实现一：先做一个人也能使用的 CLI

scripts/text_stats_cli.py

"""独立 CLI：只认识命令行参数，不知道 Agent、工具注册表或模型。"""

import argparse
import json
import os


def main():
    parser = argparse.ArgumentParser(description="统计 Unicode 码点数量")
    parser.add_argument("text", help="待统计文本；用 -- 结束选项解析")
    args = parser.parse_args()
    # argparse 默认返回 Any；在入口确认形状后再使用。
    text = args.text
    if not isinstance(text, str):
        parser.error("text 必须是字符串")
    print(json.dumps({"characters": len(text), "pid": os.getpid()}, ensure_ascii=False))


if __name__ == "__main__":
    main()

CLI 只依赖 Python 标准库。stdout 保持为单个 JSON 结果；argparse 的用法错误会写入 stderr 并非零退出。这里 len(text) 数的是 Unicode 码点，组合字符、部分 emoji 与视觉上的“一个字”不一定一一对应。空字符串是合法输入。

uv run python scripts/text_stats_cli.py -- "你好世界"
uv run python scripts/text_stats_cli.py -- ""
uv run python scripts/text_stats_cli.py -- "--help"
uv run python scripts/text_stats_cli.py

前三次 characters 分别为 4、0、6，pid 每次可能不同。最后一次缺少参数，应看到用法错误；紧接着运行 echo $?，应为 2。此时只证明 CLI 自己能运行，还没有模型参与。

05动手实现二：宿主通过执行器启动 CLI

新建下面的执行器。先抓主线：create_subprocess_exec 启动 → 两根管道同时读取 → 等待退出 → 返回 CliResult。其余代码是在保护这条主线的生命周期。执行器不知道 text_stats 的业务含义。

app/services/cli_executor.py

import asyncio
from contextlib import suppress
from dataclasses import dataclass
from pathlib import Path


@dataclass(frozen=True)
class CliResult:
    returncode: int | None
    stdout: str
    stderr: str
    truncated: bool
    error: str | None = None


async def read_bounded(reader: asyncio.StreamReader, keep_bytes: int):
    """只保留前 keep_bytes 字节,但继续排空管道,避免子进程卡在写入。"""
    saved = bytearray()
    total = 0
    while chunk := await reader.read(4096):
        total += len(chunk)
        saved.extend(chunk[: max(0, keep_bytes - len(saved))])
    # 截断可能落在一个汉字中间,replace 显式替换残缺字符。
    return saved.decode("utf-8", errors="replace"), total > keep_bytes


async def run_cli(argv: list[str], cwd: Path, timeout: float = 2.0, keep_bytes: int = 4096):
    if not argv or timeout <= 0 or keep_bytes < 0:
        raise ValueError("argv 不能为空,timeout 必须为正,keep_bytes 不能为负")
    try:
        proc = await asyncio.create_subprocess_exec(
            *argv,
            cwd=cwd,
            stdin=asyncio.subprocess.DEVNULL,
            stdout=asyncio.subprocess.PIPE,
            stderr=asyncio.subprocess.PIPE,
        )
    except OSError as exc:
        return CliResult(None, "", "", False, f"启动失败:{exc}")
    assert proc.stdout is not None and proc.stderr is not None
    # 两根管道同时排空。只读 stdout,可能被写满的 stderr 反向阻塞。
    out_task = asyncio.create_task(read_bounded(proc.stdout, keep_bytes))
    err_task = asyncio.create_task(read_bounded(proc.stderr, keep_bytes))
    error: str | None = None
    # 提前初始化，保证异常分支下变量也已绑定；类型由初始值推导。
    out, err = "", ""
    out_cut, err_cut = False, False
    try:
        async with asyncio.timeout(timeout):
            await proc.wait()
            out, out_cut = await out_task
            err, err_cut = await err_task
    except TimeoutError:
        error = "执行超时"
    finally:
        # 超时或上层取消都要回收子进程。取消异常不会变成成功结果。
        if proc.returncode is None:
            with suppress(ProcessLookupError):
                proc.kill()
        await proc.wait()
        for task in (out_task, err_task):
            if not task.done():
                task.cancel()
        await asyncio.gather(out_task, err_task, return_exceptions=True)
    if error is not None:
        return CliResult(proc.returncode, "", "", False, error)
    return CliResult(proc.returncode, out, err, out_cut or err_cut)

read_bounded 对每根管道各保留最多 4096 字节，达到预算后继续读取但不保存，避免堵住子进程。truncated 为真时适配器会拒绝结果。decode 的替换字符可能令重新编码后的长度略超预算，预算约束的是保存的原始字节。

TimeoutError 转为错误结果；上层 CancelledError 经过 finally 清理后继续传播。输出变量提前初始化，异常路径也不会出现“可能未赋值”。这个实现只管理直接子进程，适用于本课不派生后代的 CLI；反复取消清理任务、进程树监管需另行设计。

06动手实现三：把 CLI 接到工具注册表

在 app/services/tools.py 合并以下 import，把结果模型与 _text_stats 放在 TOOL_REGISTRY 定义之前。该文件已有 json 导入，直接复用。不要用以下片段覆盖整个文件，保留天气、时间、RAG 与 MCP 的现有代码。

app/services/tools.py（适配器片段）

# 合并到 tools.py 顶部 import 区；已有 json 不要重复导入。
import sys
from pathlib import Path

from pydantic import BaseModel, ConfigDict, Field, ValidationError

from app.services.cli_executor import run_cli


class TextStatsResult(BaseModel):
    # stdout 是外部数据：既检查 JSON，也检查字段类型与范围。
    model_config = ConfigDict(strict=True, extra="forbid")
    characters: int = Field(ge=0)
    pid: int = Field(gt=0)


async def _text_stats(args: dict[str, object]):
    text = args.get("text")
    if not isinstance(text, str):
        return json.dumps({"error": "text 必须是字符串"}, ensure_ascii=False)
    if len(text) > 1000:
        return json.dumps({"error": "本实验最多接受 1000 个码点"}, ensure_ascii=False)

    # tools.py 位于 app/services/；parents[2] 是项目根目录。
    root = Path(__file__).resolve().parents[2]
    script = root / "scripts" / "text_stats_cli.py"
    # 模型只提供 text；程序、脚本位置与超时由宿主固定。
    result = await run_cli([sys.executable, str(script), "--", text], root)
    if result.error is not None:
        return json.dumps({"error": result.error}, ensure_ascii=False)
    if result.returncode != 0:
        return json.dumps(
            {"error": "CLI 非零退出", "returncode": result.returncode, "stderr": result.stderr},
            ensure_ascii=False,
        )
    if result.truncated:
        return json.dumps({"error": "CLI 输出被截断，不能作为完整结果"}, ensure_ascii=False)
    try:
        parsed = TextStatsResult.model_validate_json(result.stdout)
    except ValidationError:
        return json.dumps({"error": "CLI 输出不符合统计结果合同"}, ensure_ascii=False)
    return parsed.model_dump_json()

这里有两个外部数据入口：模型参数用 isinstance 检查；CLI 的 stdout 用 Pydantic 建模。execute_tool 当前只检查必填键，不检查 text 的值类型，所以适配器仍需校验。退出码为 0 只说明进程成功退出；还必须通过业务结果合同。若未来 CLI 自带业务错误字段，需把它加入合同并明确处理。

app/services/tools.py（注册片段）

# 放在现有 TOOL_REGISTRY 和 TOOLS_SCHEMA 都定义完成之后；只添加一次。

先绕过模型，直接验证 execute_tool → CLI

scripts/t2_tool_smoke.py

"""先验证工具分发与真实子进程，不请求模型。"""

import asyncio
import json
import os

from app.services.tools import TextStatsResult, execute_tool


async def main():
    for text in ("你好世界", "", "--help", "你好; echo unsafe"):
        raw = await execute_tool("text_stats", json.dumps({"text": text}, ensure_ascii=False))
        result = TextStatsResult.model_validate_json(raw)
        assert result.characters == len(text)
        assert result.pid != os.getpid()  # 业务结果来自另一个进程。
        print("原文:", repr(text), "宿主 PID:", os.getpid(), "CLI 结果:", raw)
    for args in ({}, {"text": 123}, {"text": "x" * 1001}):
        raw = await execute_tool("text_stats", json.dumps(args))
        assert "error" in raw
        print("预期错误:", raw)


if __name__ == "__main__":
    asyncio.run(main())

项目已有 run_agent 与 run_agent_stream，都经过 execute_tool；本课复用非流式 run_agent，先把轨迹看清。以下是现有循环的关键动作摘录，仅用于阅读，不要再复制一套到 agent.py。

# ① 每轮把工具说明交给模型
response = await llm_client.chat_with_tools(messages, tool_params)

# ② 保存模型的 assistant 工具调用消息，然后逐条执行

scripts/t2_agent_demo.py

"""真实模型端到端实验；使用已有 run_agent，不复制 Agent 循环。"""

import asyncio
import os

from app.services.agent import build_llm_messages, run_agent
from app.services.tools import TextStatsResult


async def main():
    messages = build_llm_messages([])
    messages.append({
        "role": "user",
        "content": "请调用 text_stats 工具统计原文‘你好世界’的 Unicode 码点数，原文不含引号。",
    })
    answer, trace = await run_agent(messages)
    print("宿主 PID:", os.getpid())
    call_ids: set[str] = set()
    verified = False
    for message in trace:
        print(message)  # 展示 assistant 申请单、tool 结果和最终回答。
        for call in message.get("tool_calls") or []:
            if call["function"]["name"] == "text_stats":
                call_ids.add(call["id"])
        if message["role"] == "tool" and message.get("tool_call_id") in call_ids:
            result = TextStatsResult.model_validate_json(message.get("content") or "")
            assert result.characters == 4
            assert result.pid != os.getpid()
            verified = True
    assert verified, "没有找到匹配的 CLI 工具结果；答对数字也不算调用成功"
    print("最终回答:", answer)


if __name__ == "__main__":
    asyncio.run(main())

本课不要求修改 agent.py。以后通过现有 HTTP 接口使用时，重启服务使注册生效，原 agentic loop 就会看到新工具；路由的会话、持久化与并发控制仍由已有代码负责。

08思考题：沿调用边界解释原因

为什么不直接 import CLI 的 main？

那会变成进程内函数调用，绕过命令行参数、stdout、退出码与独立进程边界。复用 Python 库当然可以，但那是另一种工具实现方式。

模型知道 text_stats_cli.py 在哪里吗？

本课不需要。模型只看工具说明，宿主在适配器中固定路径；路径、解释器和超时没有交给模型选择。

为什么不能把 stdout 直接当最终回答？

stdout 是工具结果。Agent 需把它关联到原 tool_call_id，再交给模型继续推理或组织回答；另外 stdout 仍需校验，可能是报错文本或错误形状。

为什么 stdout 与 stderr 必须一起读？

任何一根管道写满都可能阻塞子进程。先等退出再读，或者先完整读完一根再读另一根，都可能死锁。

CLI 启动成功是否等于任务成功？

分三层判断：能否启动、退出码是否成功、业务输出是否有效。超时与截断也不能当作完整成功。

为什么例子很小却还用 CLI？

为了把跨进程接口显露出来。实际能力可以来自已有命令行程序，Agent 不必把其业务逻辑重新写一遍；选择 CLI 是复用能力的方式，不是所有工具必须走的步骤。

09验证实验：正常、边界和失败路径

主链走通后再做执行器实验。故障由测试启动的 Python 小程序制造，不往业务 CLI 塞 --worker、--mode 或测试入口。

scripts/t2_executor_checks.py

"""执行器行为测试：真实启动子进程，不调用模型。"""

import asyncio
import sys
from pathlib import Path

from app.services.cli_executor import run_cli


async def main():
    cwd = Path.cwd()
    ok = await run_cli([sys.executable, "-c", "print('ok')"], cwd)
    assert ok.returncode == 0 and ok.stdout.strip() == "ok"
    fail = await run_cli([sys.executable, "-c", "import sys; sys.stderr.write('bad'); sys.exit(3)"], cwd)
    assert fail.returncode == 3 and fail.stderr == "bad"
    flood = await run_cli(
        [sys.executable, "-c", "import sys; print('x'*100000); sys.stderr.write('y'*100000)"],
        cwd, keep_bytes=64,
    )
    assert flood.returncode == 0 and flood.truncated
    assert len(flood.stdout) == len(flood.stderr) == 64
    slow = [sys.executable, "-c", "import time; time.sleep(10)"]
    result = await run_cli(slow, cwd, timeout=0.1)
    assert result.error == "执行超时" and result.returncode is not None
    missing = await run_cli([str(cwd / "__t2_missing_executable__")], cwd)
    assert missing.error is not None and missing.returncode is None
    task = asyncio.create_task(run_cli(slow, cwd))
    await asyncio.sleep(0.1)  # 仅测试中让子进程进入等待，再触发取消。
    task.cancel()
    try:
        await task
    except asyncio.CancelledError:
        pass
    else:
